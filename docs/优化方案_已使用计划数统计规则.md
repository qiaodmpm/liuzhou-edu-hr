# 优化方案：已使用计划数统计规则

**版本**: v1.0  
**日期**: 2026-06-24  
**状态**: 待确认

---

## 一、规则变更

| 项目 | 旧规则 | 新规则 |
|------|--------|--------|
| 已使用计划数 | = 已入编人数（usedCount） | = 已占用 + 已入编（occupiedCount + usedCount） |
| 未使用计划数公式 | = 已批复 − 已占用 − 已入编 | = 已批复 − 已使用（数学等价，表述更简洁） |

### 语义解释

- **已占用（occupiedCount）**: 招聘/调动流程中，已被"预定"但尚未正式入编的人数
- **已入编（usedCount）**: 已正式落编的终态人数
- **已使用（usedPlan）** = 已占用 + 已入编 → 这块编制名额已经"花出去了"，不再可用

## 二、影响范围

### 2.1 `src/ledger-plan-utils.js` — `computeAggregates()`

**改动 1**: occupiedCount / usedCount 仅对有效期内计划求和（与 approvedPlan 对齐）

```js
// 将 occupiedPlan 和 usedPlan 的累加移入非到期分支
if (st === PLAN_STATUS.EXPIRED) {
  unusedExpired += remainingCount(p);
} else {
  approvedPlan += (p.adjustedApprovedCount || 0);
  occupiedPlan += (p.occupiedCount || 0);   // 移入
  usedPlan += (p.usedCount || 0);            // 移入
  if (st !== PLAN_STATUS.EXHAUSTED) {
    unusedActive += remainingCount(p);
  }
}
```

**改动 2**: usedPlan 返回值改为 occupiedPlan + usedPlan

```js
return {
  approvedPlan: approvedPlan,
  occupiedPlan: occupiedPlan,                       // 不变：占用数（供明细展示）
  usedPlan: occupiedPlan + usedPlan,                // 改动：已使用 = 已占用 + 已入编
  unusedPlan: unusedActive + unusedExpired,
  unusedActive: unusedActive,
  unusedExpired: unusedExpired
};
```

> 注意：`occupiedPlan` 仍独立返回，供计划明细弹框的汇总行展示占用/已入编的细分。

### 2.2 `src/ledger-plan-utils.js` — `remainingCount()`

公式不变：`Math.max(0, adjustedApprovedCount - occupiedCount - usedCount)`

等价于：`已批复 − 已使用`，无需改代码。

### 2.3 `src/ledger-migrate.js` — `syncAggregatesFromPlans()`

无需改动。它直接赋值 `computeAggregates()` 的返回值，自动适配。

## 四、验证要点

1. ✅ 计划明细弹框汇总：已使用 = 占用 + 已入编
2. ✅ 编辑表单：已使用计划数 = 占用 + 已入编（readonly，自动计算）
3. ✅ 未使用计划数 = 已批复 − 已使用，数值不变（公式等价）
4. ✅ 已到期计划的占用/入编不计入已使用

## 五、风险评估

- **低风险**：仅涉及聚合计算逻辑，不改变数据结构，不涉及 localStorage 迁移
- 计划明细表格的独立列（已占用 / 已入编）不受影响，仅汇总数字的统计口径变化
