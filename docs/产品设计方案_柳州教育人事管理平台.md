# 柳州市教育局统一教育人事管理平台 — 产品设计方案

## 1. 项目概述

### 1.1 项目背景

柳州市教育局下辖多个区教育局及市直属学校，目前教师人事管理依赖线下填报、逐级审批，存在以下痛点：

- 数据分散在各区、各校，缺乏统一标准，汇总统计困难
- 纸质审批流转周期长，跨层级沟通成本高
- 编制、岗位、聘用等核心数据难以实时掌握，影响决策效率
- 教师个人档案信息分散，缺乏全生命周期管理

### 1.2 项目目标

| 目标 | 说明 |
|------|------|
| 业务线上化 | 编制、岗位、聘用、退休、工资、考核、荣誉全流程在线办理 |
| 分级权限管理 | 市、区、校、教师四级角色，数据按权限隔离 |
| 灵活统计导出 | 支持单条/汇总数据统计，多维度筛选，一键导出 |
| 双模式发起 | 支持教师自主申请 + 教育局/学校公告批次申请 |
| 差异化审批 | 除招聘需三级审批外，其余业务均为两级审批；市直属学校跳过区级 |

### 1.3 核心业务审批总览

| 业务模块 | 发起人 | 区属学校审批路径 | 市直属学校审批路径 |
|---------|--------|----------------|------------------|
| 入编申请 | 教师 | 教师→学校→区教育局（终审） | 教师→学校→市教育局（终审） |
| 编制使用申请 | 学校管理员 | 学校→区教育局（终审） | 学校→市教育局（终审） |
| 教师出编管理 | 学校管理员 | 学校→区教育局（终审） | 学校→市教育局（终审） |
| 岗位晋升申请 | 教师 | 教师→学校→区教育局（终审） | 教师→学校→市教育局（终审） |
| 岗位设置申请 | 学校管理员 | 学校→区教育局（终审） | 学校→市教育局（终审） |
| **招聘岗位申请** | 学校管理员 | **学校→区教育局（初审）→市教育局（终审）** | 学校→市教育局（终审） |
| 聘用手续办理 | 学校管理员 | 学校→区教育局（终审） | 学校→市教育局（终审） |
| 退休呈报 | 学校管理员 | 学校→区教育局（终审） | 学校→市教育局（终审） |
| 工资核定申请 | 学校管理员 | 学校→区教育局（终审） | 学校→市教育局（终审） |
| 师德师风举报 | 教师 | 教师→学校（处理），严重上报区教育局 | 教师→学校（处理），严重上报市教育局 |
| 荣誉申请 | 教师 | 教师→学校→区教育局（终审） | 教师→学校→市教育局（终审） |

> **关键规则**:
> - 招聘岗位申请是**唯一三级审批**业务（区属学校：校→区初审→市终审）
> - 市直属学校所有业务均为**两级审批**（校→市终审），不经过区级
> - 师德师风举报为**特殊处理流程**，学校先行处理，仅严重情形逐级上报

### 1.4 适用范围

- **机构范围**: 柳州市教育局、各区教育局、全市中小学（含市直属、区属）
- **人员范围**: 在编教师、聘用教师、行政管理人员、离退休人员
- **业务范围**: 入编申请、编制使用申请、教师出编管理、岗位晋升申请、岗位设置申请、招聘岗位申请、聘用手续办理、退休呈报、工资核定申请、师德师风举报、荣誉申请

## 2. 用户角色与权限体系

### 2.1 角色定义

```
市级管理员 —— 市教育局人事科，全局数据查看与审批
  ├── 区级管理员 —— 区教育局人事股，辖区数据管理与审批
  │     ├── 校级管理员 —— 学校人事干部，本校数据录入与初审
  │     │     └── 教师 —— 个人申请、信息查看
  │     └── 教师（直属）—— 市直属学校教师
  └── 系统管理员 —— 平台运维，账号管理与配置
```

### 2.2 权限矩阵

| 功能模块 | 市管理员 | 区管理员 | 校管理员 | 教师 |
|---------|---------|---------|---------|------|
| 查看全市数据 | ● | ○（辖区） | ○（本校） | ○（本人） |
| 审批普通业务 | 终审 | 初审/终审 | 初审 | — |
| 审批招聘业务 | 终审 | 二审 | 初审 | — |
| 发布公告批次 | ● | ● | ● | — |
| 发起自主申请 | — | — | — | ● |
| 数据导出 | ● | ○（辖区） | ○（本校） | ○（本人） |
| 编制管理 | ● | ○（辖区） | — | — |
| 岗位设置 | ● | ○（辖区） | — | — |
| 系统配置 | ● | — | — | — |

> ● 全部权限 ○ 限定范围权限 — 无权限

### 2.3 账号体系

- 教师账号：以身份证号或教职工编号为唯一标识，初始密码由管理员下发，首次登录强制修改
- 管理员账号：由上级管理员创建，绑定手机号，支持短信验证登录
- 支持与现有教育系统（如全国教师管理信息系统）数据对接，减少重复录入

## 3. 核心功能模块

### 3.1 入编申请

**发起人**: 教师
**业务描述**: 新入职教师（公开招聘录用、调入等）的编制入编登记。

| 审批路径 | 流程 |
|---------|------|
| 区属学校 | 教师提交→学校审核→区教育局（终审） |
| 市直属学校 | 教师提交→学校审核→市教育局（终审） |

**关键字段**: 姓名、身份证号、教职工编号、入编时间、编制类型（专业技术/管理/工勤）、聘用岗位、学历信息、入职文件（附件）

**业务规则**:
- 需在编制空编范围内方可入编，超编则自动拦截并提示
- 入编后自动更新学校编制台账（实有人数+1）
- 支持批量导入（公开招聘批次录用场景）

---

### 3.2 编制使用申请

**发起人**: 学校管理员
**业务描述**: 学校在空编范围内申请使用编制（用于招聘、调入等）。

| 审批路径 | 流程 |
|---------|------|
| 区属学校 | 学校提交→区教育局（终审） |
| 市直属学校 | 学校提交→市教育局（终审） |

**关键字段**: 申请编制数量、编制类型、使用事由（公开招聘/调入/其他）、计划使用时间、岗位需求说明

**业务规则**:
- 申请数 ≤ 当前空编数，超额无法提交
- 审批通过后冻结相应空编额度，后续入编消耗该额度
- 年度编制使用计划汇总，支持按学校、区域统计编制使用效率

---

### 3.3 教师出编管理

**发起人**: 学校管理员
**业务描述**: 教师因退休、调出、辞职、辞退、死亡等原因出编。

| 审批路径 | 流程 |
|---------|------|
| 区属学校 | 学校提交→区教育局（终审） |
| 市直属学校 | 学校提交→市教育局（终审） |

**关键字段**: 教师姓名、教职工编号、出编原因（退休/调出/辞职/辞退/死亡/其他）、出编日期、相关证明材料（附件）

**业务规则**:
- 出编审批通过后自动释放编制额度（实有人数-1，空编数+1）
- 出编记录与教师档案关联，标记该教师在系统中的状态为"已出编"
- 退休出编与退休呈报模块联动，退休审批通过后可自动触发

---

### 3.4 岗位晋升申请

**发起人**: 教师
**业务描述**: 教师符合晋升条件后，自主申请岗位等级晋升（如初级→中级、中级→高级）。

| 审批路径 | 流程 |
|---------|------|
| 区属学校 | 教师提交→学校审核→区教育局（终审） |
| 市直属学校 | 教师提交→学校审核→市教育局（终审） |

**岗位等级结构**:

```
专业技术岗位
├── 高级岗位（五级/六级/七级）
├── 中级岗位（八级/九级/十级）
└── 初级岗位（十一级/十二级/十三级）
```

**关键字段**: 现岗位等级、申请晋升等级、符合条件说明、任现职年限、考核结果摘要、相关证书/文件（附件）

**业务规则**:
- 晋升前校验目标等级是否有空缺岗位，无空缺则提示"该等级岗位已满"
- 任现职年限不满足晋升条件则自动拦截
- 晋升通过后自动更新教师岗位信息、工资信息（岗位工资联动调整）
- 支持按公告批次方式批量发起（如年度职称评审）

---

### 3.5 岗位设置申请

**发起人**: 学校管理员
**业务描述**: 学校根据人社部门规定，制定或调整本校岗位设置方案（各级岗位数量分配）。

| 审批路径 | 流程 |
|---------|------|
| 区属学校 | 学校提交→区教育局（终审） |
| 市直属学校 | 学校提交→市教育局（终审） |

**关键字段**: 学校名称、岗位设置周期、各级岗位核定数（五级~十三级）、学科分布、方案说明

**业务规则**:
- 岗位比例需符合人社部门规定（高级:中级:初级比例）
- 岗位设置方案是岗位晋升申请的前置条件，未设置则无法发起晋升
- 审批通过后生成学校的"岗位设置台账"，作为后续聘任的依据

---

### 3.6 招聘岗位申请

**发起人**: 学校管理员
**业务描述**: 学校提交年度或专项公开招聘计划，明确招聘岗位、人数及条件。

| 审批路径 | 流程 |
|---------|------|
| 区属学校 | 学校提交→区教育局（**初审**）→市教育局（**终审**） |
| 市直属学校 | 学校提交→市教育局（终审） |

> 这是**唯一一个三级审批**业务（针对区属学校），体现了公开招聘的严格管控。

**关键字段**: 招聘年度、学科岗位、招聘人数、学历要求、年龄要求、专业要求、是否应届、备注说明

**业务规则**:
- 招聘人数 ≤ 空编数（需先通过编制使用申请获得额度）
- 区属学校: 区教育局初审通过后提交市教育局终审，两级均可退回
- 市直属学校: 直接市教育局终审
- 终审通过后生成"招聘岗位计划"，可作为后续入编申请和聘用手续的前置依据

---

### 3.7 聘用手续办理

**发起人**: 学校管理员
**业务描述**: 学校为新入职人员或聘用变更人员办理正式聘用手续。

| 审批路径 | 流程 |
|---------|------|
| 区属学校 | 学校提交→区教育局（终审） |
| 市直属学校 | 学校提交→市教育局（终审） |

**关键字段**: 教师姓名、聘用类型（首次聘用/续聘/岗位变动聘用）、聘用起始日期、聘用期限、聘用岗位等级、聘用合同（附件）

**业务规则**:
- 首次聘用需关联招聘计划或调入文件
- 聘用合同到期前3个月自动提醒续签
- 聘用手续办结后，教师聘用状态更新，岗位信息同步

---

### 3.8 退休呈报

**发起人**: 学校管理员
**业务描述**: 学校为即将退休的教师呈报退休审批。

| 审批路径 | 流程 |
|---------|------|
| 区属学校 | 学校提交→区教育局（终审） |
| 市直属学校 | 学校提交→市教育局（终审） |

**关键字段**: 教师姓名、出生日期、参加工作时间、退休时间、退休类型（正常退休/提前退休/延迟退休）、呈报材料（附件）

**业务规则**:
- 系统根据出生日期和政策规则，提前6个月自动生成退休预警名单
- 男性60周岁、女性55周岁为正常退休年龄
- 女性高级职称教师可申请延迟至60周岁退休，需额外提交延迟退休申请表
- 退休呈报审批通过后，可联动触发教师出编管理

---

### 3.9 工资核定申请

**发起人**: 学校管理员
**业务描述**: 学校为教师办理工资核定或工资变动审批。

| 审批路径 | 流程 |
|---------|------|
| 区属学校 | 学校提交→区教育局（终审） |
| 市直属学校 | 学校提交→市教育局（终审） |

**工资结构**:

| 工资项目 | 说明 |
|---------|------|
| 岗位工资 | 按岗位等级确定 |
| 薪级工资 | 按薪级确定（年度考核合格升1级） |
| 绩效工资 | 基础性绩效 + 奖励性绩效 |
| 教龄津贴 | 按教龄年限发放 |
| 乡镇工作补贴 | 乡镇学校教师专属 |
| 特级教师津贴 | 特级教师专属 |

**关键字段**: 教师姓名、变动类型（初次核定/岗位晋升调资/薪级晋升调资/政策调标）、工资项目明细、执行起始时间、审批材料（附件）

**业务规则**:
- 与岗位晋升联动：岗位等级变化自动触发工资变动提醒
- 与考核联动：年度考核合格以上自动触发薪级晋升（薪级+1）
- 工资变动历史完整记录，形成教师个人工资台账

---

### 3.10 师德师风举报

**发起人**: 教师（举报人）
**业务描述**: 教师举报师德师风违规行为，学校先行处理，严重情形逐级上报。

| 审批路径 | 流程 |
|---------|------|
| 区属学校 | 教师举报→学校（处理），情节严重上报区教育局 |
| 市直属学校 | 教师举报→学校（处理），情节严重上报市教育局 |

> 这是**特殊处理流程**——学校先行调查处理，不严重则校内闭环；情节严重/涉及校领导时逐级上报。

**关键字段**: 被举报人姓名、所属学校、举报事项描述、证据材料（附件）、举报人信息（支持实名/匿名）

**业务规则**:
- 举报受理后学校须在规定时限内处理并反馈
- 学校判定为"严重"的情形：涉及违法犯罪、造成恶劣社会影响、涉及校级领导
- 匿名举报同样受理，但需提供充分证据
- 全程记录处理过程和结果，形成师德档案
- 举报人信息严格保密，仅处理该举报的管理员可见

---

### 3.11 荣誉申请

**发起人**: 教师
**业务描述**: 教师自主申报或学校推荐各类荣誉奖项。

| 审批路径 | 流程 |
|---------|------|
| 区属学校 | 教师提交→学校审核→区教育局（终审） |
| 市直属学校 | 教师提交→学校审核→市教育局（终审） |

**荣誉类型**:

| 类型 | 示例 |
|------|------|
| 综合荣誉 | 优秀教师、先进教育工作者、劳动模范 |
| 教学荣誉 | 教学名师、学科带头人、骨干教师、教坛新秀 |
| 科研荣誉 | 教学成果奖、课题成果 |
| 竞赛荣誉 | 教学竞赛获奖、指导学生获奖 |

**关键字段**: 荣誉名称、荣誉级别（国家级/省部级/市级/区级/校级）、获得日期、颁发单位、荣誉证书（附件）、有效期

**业务规则**:
- 支持自主申请和学校推荐两种方式
- 荣誉可按公告批次方式统一组织评选（如年度优秀教师评选）
- 荣誉到期前自动提醒（如骨干教师聘期3年，到期前3个月提醒）
- 荣誉信息计入教师个人档案，作为岗位晋升、评优评先的参考依据

## 4. 业务流程设计

### 4.1 两种发起模式

#### 模式A：自主申请

适用场景：教师个人发起岗位晋升、荣誉申报、调动申请等。

```
教师填写申请表 → 学校管理员审核 → 区/市教育局审批 → 结果反馈教师
```

- 教师端：我的申请（草稿/审核中/已通过/已退回）
- 管理员端：待办事项提醒，支持批量审核

#### 模式B：公告批次申请

适用场景：教育局或学校统一发起年度考核、职称评审、招聘等批量业务。

```
管理员创建批次 → 设置起止时间 → 发布公告 → 教师按批次提交 → 批量审核 → 批量审批
```

- 批次管理：批次名称、起止时间、业务类型、参与范围、当前状态
- 批量操作：批量审核通过、批量退回、批量导出

---

### 4.2 审批路径规则

#### 规则一：按学校归属决定审批层级

```
区属学校:  发起人 → 学校 → 区教育局（终审）
市直属学校: 发起人 → 学校 → 市教育局（终审）
```

所有业务（除招聘岗位申请外）均遵循此两级审批模式，市直属学校不经过区级。

#### 规则二：招聘岗位申请（唯一三级审批）

```
区属学校:     学校 → 区教育局（初审） → 市教育局（终审）
市直属学校:   学校 → 市教育局（终审）
```

招聘岗位申请是**唯一**需要三级审批的业务——区属学校须经过区教育局初审后，再报市教育局终审。体现了公开招聘编制使用需区市两级人事部门共同把关的管理要求。

#### 规则三：师德师风举报（特殊处理流程）

```
区属学校:     教师举报 → 学校调查处理 → 情节严重→上报区教育局
市直属学校:   教师举报 → 学校调查处理 → 情节严重→上报市教育局
```

学校为第一处理主体，处理完毕形成闭环。仅在涉及违法犯罪、造成恶劣影响、涉及校领导等严重情形时，才启动逐级上报。举报人信息全程保密。

#### 审批路径速查表

| 业务模块 | 区属学校审批链 | 市直属学校审批链 |
|---------|--------------|----------------|
| 入编申请 | 教师→校→区 | 教师→校→市 |
| 编制使用申请 | 校→区 | 校→市 |
| 教师出编管理 | 校→区 | 校→市 |
| 岗位晋升申请 | 教师→校→区 | 教师→校→市 |
| 岗位设置申请 | 校→区 | 校→市 |
| **招聘岗位申请** | **校→区(初审)→市(终审)** | 校→市 |
| 聘用手续办理 | 校→区 | 校→市 |
| 退休呈报 | 校→区 | 校→市 |
| 工资核定申请 | 校→区 | 校→市 |
| 师德师风举报 | 教师→校(处理)，严重→区 | 教师→校(处理)，严重→市 |
| 荣誉申请 | 教师→校→区 | 教师→校→市 |

## 5. 数据架构设计

### 5.1 核心数据实体

```
机构 (Organization)
  ├── 机构ID、名称、类型（市局/区局/学校）
  ├── 上级机构ID（层级关系）
  ├── 所属区域、学段、办学性质
  └── 编制总数、岗位设置方案

教师 (Teacher)
  ├── 基本信息：姓名、性别、出生日期、身份证号
  ├── 人事信息：教职工编号、编制类型、聘用状态
  ├── 岗位信息：现任岗位、岗位等级、聘用时间
  ├── 工资信息：岗位工资、薪级工资、薪级
  ├── 学历信息：最高学历、毕业院校、专业
  └── 工作经历：入职时间、教龄、校内职务

业务申请 (Application)
  ├── 申请ID、业务类型、发起方式
  ├── 申请人、所属机构、提交时间
  ├── 当前状态、当前审批节点
  ├── 表单数据（JSON，按业务类型动态配置）
  └── 审批记录列表

审批记录 (ApprovalRecord)
  ├── 审批人、审批机构、审批时间
  ├── 审批结果（通过/退回）、审批意见
  └── 审批节点（初审/二审/终审）

公告批次 (Batch)
  ├── 批次名称、业务类型、起止时间
  ├── 发布机构、参与范围（机构列表）
  ├── 批次状态（草稿/进行中/已结束）
  └── 关联申请列表
```

### 5.2 数据权限策略

| 角色 | 可见数据范围 |
|------|------------|
| 市管理员 | 全市所有数据 |
| 区管理员 | 本区及下属学校数据 |
| 校管理员 | 本校数据 |
| 教师 | 本人数据 + 公开公告 |

- 机构树数据隔离：用户只能查看所属机构及下属机构数据
- 敏感字段脱敏：身份证号、手机号等在前端列表页默认脱敏展示
- 操作日志记录：所有数据变更操作记录操作人、时间、IP

## 6. 系统架构建议

### 6.1 技术选型建议

| 层面 | 建议方案 | 说明 |
|------|---------|------|
| 前端 | Vue 3 + Element Plus | 政务系统主流技术栈，组件丰富 |
| 后端 | Java / Spring Boot | 与现有政务系统对接兼容性好 |
| 数据库 | PostgreSQL + Redis | 支持JSON字段（灵活表单），缓存提升性能 |
| 文件存储 | MinIO / OSS | 附件上传、电子签章文件存储 |
| 部署 | 政务云 + Docker | 符合政务系统安全要求 |

### 6.2 核心非功能性需求

- **安全性**: 等保二级及以上，数据加密传输，操作日志审计
- **可用性**: 支持500+并发用户，高峰期（9月开学）稳定运行
- **可扩展性**: 表单配置化，业务类型可动态扩展，无需改代码
- **对接能力**: 预留与全国教师管理信息系统、人社系统、编办系统的数据接口

### 7.2 关键页面设计要点

- **工作台**: 首页展示待办事项数量、关键数据概览卡片、业务快捷入口、通知公告
- **列表页**: 统一的多条件筛选（时间范围、业务类型、状态、机构层级）+ 批量操作 + 导出按钮
- **表单页**: 分步填写（基本信息→业务信息→附件上传），自动校验，暂存草稿
- **详情页**: 业务流程进度条可视化，审批记录时间线，数据变更历史
- **统计看板**: 图表可视化（编制使用率、岗位空缺统计、考核等级分布等）

- 教师端支持移动端自主申请（微信小程序/H5），方便教师随时提交申请
- 管理员端支持移动端审批（审批通过/退回/转办）
- 消息推送：审批进度变更实时通知教师
