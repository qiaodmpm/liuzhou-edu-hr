> 版本：v1.0  
> 更新日期：2026-06-11  
> 本文档为平台总纲，各模块详细需求见子文档。

## 第一章 项目概述

### 1.1 项目背景

柳州市教育局下辖多个区教育局及市直属学校，教师人事管理长期依赖线下填报、纸质审批，存在以下痛点：

- 数据分散在各区、各校，缺乏统一标准，汇总统计困难
- 纸质审批流转周期长，跨层级沟通成本高
- 编制、岗位、聘用等核心数据难以实时掌握，影响决策效率
- 教师个人档案信息分散，缺乏全生命周期管理

### 1.2 项目目标

| 目标 | 说明 |
|------|------|
| 业务线上化 | 编制、岗位、聘用、退休、工资、师德、荣誉全流程在线办理 |
| 分级权限管理 | 市、区、校、教师、系统管理员五角色，数据按权限隔离 |
| 灵活统计导出 | 支持多维度筛选、汇总统计、一键导出 CSV |
| 双模式发起 | 支持教师自主申请 + 教育局/学校公告批次申请 |
| 差异化审批 | 招聘为三级审批，其余业务为两级审批；市直属学校跳过区级 |

### 1.3 适用范围

本平台覆盖柳州市教育局及其下辖区教育局、市直属学校、区属学校的人事管理业务。当前版本为**纯前端演示系统**，所有数据为 Mock 数据，无后端服务。

### 1.4 术语定义

| 术语 | 说明 |
|------|------|
| 事业编 | 实名制事业编制，一人一岗，编办实名登记 |
| 控制数 | 备案制中小学聘用教师控制数，总量控制、备案管理 |
| 市直属 | 由市教育局直接管理的学校，审批跳过区级 |
| 区属 | 由区教育局管理的学校，需经区级审批 |
| 编制使用申请 | 学校向编办申请使用编制的批次计划 |
| 入编 | 教师正式纳入事业编制管理 |
| 出编 | 教师退出编制（退休、调出、辞职等） |
| 岗位晋升 | 教师在岗位等级体系内逐级晋升 |
| 岗位设置 | 学校设置各等级岗位数量的方案 |
| 终审 | 最终审核环节，通过后业务完结 |
| 30天修改窗口 | 终审通过后 30 天内，审批人可将"通过"改为"驳回" |
| 使用类型 | 编制批次的使用场景分类（自主招聘/统一公招/中高级人才/高层次人才） |

## 第二章 用户角色与权限

### 2.1 五级角色体系

| 角色 | 标识 | 职责范围 | 涉及业务数据 |
|------|------|---------|-------------|
| 市管理员 | `city` | 全市教育人事审批管理，查看全市数据 | 市直属学校审批 + 全市数据查看 |
| 区管理员 | `district` | 本区教育人事审批管理 | 区属学校审批 |
| 校管理员 | `school` | 本校申报提交、审核、数据管理 | 本校业务数据 |
| 教师 | `teacher` | 个人申请、查看个人记录 | 本人相关数据 |
| 系统管理员 | `admin` | 系统配置与维护 | **不涉及任何业务数据** |

### 2.2 审批权限规则

| 规则 | 说明 |
|------|------|
| 市直属跳过区级 | 市直属学校的审批由学校直达市级，不经过区级 |
| 招聘三级审批 | 招聘模块为唯一三级审批模块：学校→区初审→市终审 |
| 数据隔离 | 区管理员只能查看本区属学校数据；校管理员只能查看本校数据；教师只能查看本人数据 |
| 市管理员全量查看 | 市管理员可查看全市所有学校数据，但不能代替区级审批区属学校 |

### 2.3 系统管理员权限范围

系统管理员**仅限**以下 4 个子功能，不接触任何业务模块：

| 子功能 | 说明 |
|--------|------|
| 账号管理 | 创建、禁用、重置密码、分配角色 |
| 机构管理 | 维护学校信息（名称、类型、归属、编制数等） |
| 角色权限 | 配置角色可访问的模块和操作权限 |
| 操作日志 | 查看所有用户的操作记录（只读） |

> 详见子文档 `PRD_系统管理模块.md`

### 3.2 审批流程总图

```
教师/学校发起
     │
     ▼
  学校审核（一审）  ←── 驳回可修改重提
     │
     ▼
  区教育局审核（二审）←── 市直属学校跳过此步
     │
     ▼
  市教育局审核（终审）←── 仅招聘模块此步为三审
     │
     ▼
   已完成 / 驳回
```

### 3.3 状态流转通用规则

| 状态 | 含义 | 流转条件 |
|------|------|---------|
| `pending_first` | 待一审（学校审核） | 教师/学校提交后 |
| `first_approved` | 一审通过 | 学校管理员审核通过 |
| `first_rejected` | 一审驳回 | 学校管理员驳回 |
| `pending_second` | 待二审（区/市审核） | 一审通过并提交至上级 |
| `second_approved` | 二审通过 | 区/市管理员审核通过 |
| `second_rejected` | 二审驳回 | 区/市管理员驳回 |
| `pending_third` | 待三审 | 仅招聘/晋升模块 |
| `third_rejected` | 三审驳回 | 仅招聘/晋升模块 |
| `completed` | 已完成 | 终审通过 |

## 第四章 公共能力

### 4.1 登录与身份切换

- 登录页（`index.html`）：角色选择 + 演示账号展示
- 登录后将 `currentUser` 写入 `localStorage`（含 `role`、`name`、`id`）
- 所有内页通过侧边栏角色切换器切换演示角色
- 切换角色时跳转到对应角色的模块列表页

### 4.2 工作台

- 工作台（`workbench.html`）为各角色的仪表盘
- 展示待办数量、快捷入口、最近操作等
- 根据角色展示不同的数据卡片

### 4.3 消息通知

- 顶部导航栏铃铛图标展示未读通知数
- 审批结果、驳回原因、提醒申报等场景触发通知
- 当前为前端模拟，通知数据存储于 localStorage

### 4.4 附件上传

- 支持格式：PDF、Word（doc/docx）、Excel（xls/xlsx）、JPG、PNG
- 单文件限制：≤10MB
- 上传后显示文件名和大小，支持移除
- 审核页面支持预览和下载

### 4.5 数据导出

- 导出格式：CSV（UTF-8 BOM）
- 支持多维度筛选：区域、学校、状态、岗位类别、年度
- 导出文件名格式：`{模块名}数据导出_{日期}.csv`

## 第六章 数据模型总览

### 6.1 核心实体关系

```
学校 (School)
  │
  ├── 编制批次 (StaffingBatch)
  │     └── 关联到招聘岗位申请
  │
  ├── 岗位设置方案 (PostSetting)
  │
  ├── 教师 (Teacher)
  │     ├── 入编记录 (EntryRecord)
  │     ├── 出编记录 (ExitRecord)
  │     ├── 岗位晋升记录 (PromoteRecord)
  │     └── 荣誉记录 (HonorRecord)
  │
  ├── 招聘申请 (RecruitRecord)
  │     └── 岗位明细 (Positions[])
  │
  ├── 聘用手续 (EmployRecord)
  ├── 退休呈报 (RetireRecord)
  ├── 工资核定 (SalaryRecord)
  └── 师德举报 (EthicsReport)
```

### 6.2 通用记录字段

所有业务记录共享的基础字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 唯一标识，格式 `{模块前缀}{日期}{序号}` |
| `status` | string | 当前状态，见各模块状态枚举 |
| `schoolName` | string | 所属学校 |
| `schoolCategory` | string | 学校归属（市直属 / 区属） |
| `submitTime` | string | 提交时间 |
| `timeline` | array | 操作时间线 |

## 第七章 非功能性需求

### 7.1 技术约束

- **纯前端**：无后端服务、无数据库、无 API 调用
- **零依赖**：无 npm 运行时包，仅使用 Vanilla HTML/CSS/JS（ES2020+）
- **字体**：Google Fonts — Noto Sans SC（需网络加载）
- **兼容性**：现代浏览器（Chrome、Edge、Firefox 最新版）

### 7.2 演示数据策略

- 所有数据以硬编码 JavaScript 数组/对象形式内嵌于页面
- 通过 `localStorage` 持久化用户操作结果
- "重置演示数据"按钮清除 localStorage 恢复初始数据
- Demo 数据覆盖所有角色、学校和状态组合

### 7.3 页面命名规范

| 模式 | 用途 | 示例 |
|------|------|------|
| `*-form.html` | 创建/编辑表单 | `entry-form.html` |
| `*-detail.html` | 详情查看 | `staffing-detail.html` |
| `*-list-*.html` | 列表管理页（按角色） | `promote-list-school.html` |
| `*-audit-*.html` | 审核/审批页（按阶段） | `post-audit-first.html` |
| `*-batch.html` | 批次操作 | `promote-batch.html` |
| `*-application.html` | 申请列表 | `staffing-application.html` |

### 7.4 错误处理

- 所有页面包含 `window.onerror` 全局错误捕获
- 错误信息以红底横幅显示在页面顶部
- 提供"重新加载"按钮快速恢复
