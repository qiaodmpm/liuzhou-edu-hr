> 版本：v3.0 | 更新日期：2026-06-11 | 父文档：PRD_柳州教育人事管理平台_总纲.md

## 1. 模块概述

### 1.1 业务背景

学校在招聘教师或调动人员前，须向机构编制委员会办公室（编办）提交编制使用计划申请。编办线下审批通过后，学校方可使用编制名额。本模块实现申请、审核、编办确认的全流程线上化。

### 1.2 双轨说明

| 轨道 | 表单依据 | 编制类型 | 管理模式 |
|------|---------|---------|---------|
| 事业编 | 附件2（事业单位编制使用计划申报表） | 实名制事业编制 | 核定编制数 - 实有在编人数 - 已批复计划数 |
| 控制数 | 附件9（中小学聘用教师控制数使用计划申报表） | 备案制聘用教师控制数 | 核定控制数 - 实有控制数人数 - 已批复控制数 |

### 1.3 使用类型（6 种）

| 编码 | 名称 | 适用编制类型 |
|------|------|-------------|
| `publicRecruit` | 统一公开招聘 | 事业编 / 控制数 |
| `selfRecruit` | 单位自主实施招聘 | 事业编 / 控制数 |
| `talentMid` | 中高级人才招聘 | 事业编 / 控制数 |
| `talentHigh` | 引进高层次人才 | 事业编 / 控制数 |
| `transfer` | 调动 | 事业编 / 控制数 |
| `other` | 其他 | 事业编 / 控制数 |

### 1.4 批次类型

| 类型 | 标识 | 创建方式 | 提交限制 | 典型场景 |
|------|------|---------|---------|---------|
| **托管批次** | 管理员手动创建 | 市/区管理员在列表页"新建批次" | 每校每种编制类型限 **1 次** | 年度集中申报：市教育局发布"2026年度第一批"，各校在截止日期前提交 |
| **自主申报批次** | `AUTO-{year}` | 系统自动生成，全年存在 | **不限次数** | 紧急/零星需求：学校临时需要编制，不走年度集中申报 |

**AUTO 批次详细规则：**

| 规则 | 说明 |
|------|------|
| 生命周期 | 每年 1 月 1 日系统自动生成，12 月 31 日自动关闭 |
| 可见范围 | 市直属学校看到 `AUTO-{year}`（发布单位：市教育局）；区属学校看到 `AUTO-{year}`（发布单位：区教育局） |
| 重复提交 | 同一学校同一编制类型可多次提交，不限制次数 |
| 列表标识 | AUTO 批次卡片左侧有绿色边框，区别于托管批次的蓝色边框 |

## 2. 状态与流转

### 2.1 状态枚举

| 状态值 | 中文标签 | 含义 |
|--------|---------|------|
| `submitted` | 待一审 | 学校已提交，等待主管单位初审 |
| `first_approved` | 一审通过 | 主管单位初审通过，等待学校提交编办确认 |
| `final_submitted` | 待二审 | 学校已提交编办批复文件，等待主管单位终审 |
| `approved` | 已通过 | 编办确认完成，编制名额生效 |
| `rejected` | 已驳回 | 申请被驳回，可修改重提 |

### 2.2 状态流转图

```
学校提交 ──→ submitted
                │
        ┌───────┤
        │ 驳回  │ 通过
        ▼       ▼
    rejected  first_approved
        │       │
        │  学校上传编办文件
        │       │
        │       ▼
        │  final_submitted
        │       │
        │  ┌────┤
        │  │驳回 │ 通过
        │  ▼    ▼
        └─→ rejected  approved（终态）
         （修改重提）
```

### 2.3 各状态下角色操作

| 状态 | 校管理员 | 区/市管理员 |
|------|---------|------------|
| `submitted` | 查看 | 审核（通过/驳回） |
| `first_approved` | 提交编办确认、导出 | 查看 |
| `final_submitted` | 查看 | 审核（通过/驳回） |
| `approved` | 查看、导出、上传后续材料 | 查看、导出、下载汇总表 |
| `rejected` | 修改重提 | 查看 |

#### 4.1.4 缺失类型提示条

当学校在托管批次内只提交了一种编制类型（如只提交了事业编未提交控制数），列表顶部显示提示条：

```
⚠ 您还未提交「控制数」的申报，请尽快补充。 [立即申报 →]
```

| 属性 | 说明 |
|------|------|
| 触发条件 | 学校在此批次中事业编和控制数只有其一已提交 |
| 显示内容 | 缺失的编制类型名称 + 快捷申报链接 |
| 按钮行为 | 点击跳转新建表单页，自动选中缺失的编制类型 |
| 消失条件 | 两种编制类型均已提交，或批次已关闭 |

## 7. 编制池联动机制

### 7.1 概述

编制使用申请模块是编制生命周期的**入口**。申请通过后，批复的编制名额进入"编制可用池"，供教师入编、招聘岗位申请等下游模块关联和消耗。

### 7.2 联动数据流

```
编制使用申请 approved
        │
        ▼
  ┌─────────────────────────┐
  │  编制可用池 (staffing_submissions) │
  │  approvedPlan += 批复数            │
  │  validStart / validEnd 写入        │
  └─────────────────────────┘
        │
        ├──→ 教师入编关联 ──→ usedPlan += 入编人数
        │
        ├──→ 招聘申请关联 ──→ pendingAudit += 申请人数（提交时）
        │                   ──→ usedPlan += 终审通过人数
        │
        └──→ 教师出编通过 ──→ usedPlan -= 出编人数（释放）
```

### 7.3 编制池关键计算

| 指标 | 公式 | 说明 |
|------|------|------|
| 可用编制 | `approvedPlan - usedPlan - pendingAudit` | 入编/招聘模块的剩余名额上限 |
| 已批复 | 编办确认的累计数 | 仅 approved 状态计入 |
| 已使用 | 入编通过 + 招聘终审通过 | 实际占用 |
| 在途 | 招聘申请待审核 | 临时占坑，驳回后释放 |

### 7.4 编制有效期对下游的影响

| 状态 | 下游行为 |
|------|---------|
| 有效期内 | 入编/招聘可正常关联此编制批次 |
| 已过期 | 入编/招聘页面的批次下拉列表中不显示或标记"已过期"；不可选 |
| 即将到期（≤30天） | 黄色警告标签，仍可选但提示 |
