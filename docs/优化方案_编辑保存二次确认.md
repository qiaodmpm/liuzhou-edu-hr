# 优化方案：查看页去编辑按钮 + 编辑保存需二次确认

> 日期：2026-06-15 | 状态：方案确认中，暂未实施

---

## 一、查看页去掉编辑按钮

### 现状

查看页（`mode=view`）标题右侧有「编辑台账」按钮，点击跳转到 `mode=edit`。

### 问题

进入编辑的正确路径是从列表页直接点击「编辑」链接，而非从查看页跳转。查看页的编辑按钮是多余的入口。

### 方案

- 查看页（`mode=view`）：标题右侧不显示任何操作按钮
- 编辑入口统一从列表页的操作区进入（「编辑」链接 → `?mode=edit`）

### 改动

```diff
- } else {
-   h += '<a class="btn btn-sm btn-outline-sm" href="...&mode=edit">编辑台账</a>';
- }
+ // view 模式不显示操作按钮
```

## 二、编辑保存时二次确认弹框

### 交互流程

```
编辑页面 → 修改字段 → 点击 [保存修改]
  │
  ▼
┌─────────────────────────────┐
│  保存修改                     │
│                             │
│  修改原因 *                  │
│  ┌─────────────────────────┐│
│  │                         ││
│  └─────────────────────────┘│
│                             │
│          [取消]  [确认保存]   │
└─────────────────────────────┘
  │                    │
  │ 取消：关闭弹框      │ 确认：保存 + 跳转查看页
  └────────────────────┘
```

### 弹框规范

对齐项目 modal 样式（参考 `employ-form.html` 和现有 `returnModal`）：

```html
<div class="modal-overlay show">
  <div class="modal">
    <h3>保存修改</h3>
    <div class="form-group">
      <label>修改原因 <span style="color:var(--danger);">*</span></label>
      <textarea id="editReasonInput" rows="3" 
        placeholder="请填写本次修改的原因"></textarea>
    </div>
    <div class="btn-row">
      <button class="btn btn-outline btn-sm" onclick="closeEditModal()">取消</button>
      <button class="btn btn-primary btn-sm" onclick="confirmSaveEdit()">确认保存</button>
    </div>
  </div>
</div>
```

### 保存逻辑

```
confirmSaveEdit():
  1. 读取 editReasonInput 值
  2. 为空 → showToast('请填写修改原因', 'warning')
  3. 不为空:
     a. ledger.updatedAt = today
     b. ledger.updatedBy = currentUser.name
     c. saveLedger() 写入 localStorage
     d. close modal
     e. 跳转回查看页: ?mode=view
     f. showToast('台账修改已保存', 'success')
```

### 数据存储

每次操作（提交/审核/退回/编辑）时，将记录追加到变更日志数组：

```javascript
// 台账数据新增字段
ledger.changeLog = [];
```

每条记录结构：
```javascript
{
  type: 'edit',                              // submit | approve | return | edit
  time: '2026-06-15 14:30:00',               // 操作时间
  operator: '张建国',                         // 操作人
  action: '审核通过',                         // 操作描述（非 edit 类型）
  reason: '编制数由编办最新批复调整为92',       // 原因（edit/return 类型）
  changes: {                                 // 变更明细（仅 edit 类型）
    careerQuota: { old: 88, new: 92 }
  }
}
```

### 3.3 变更日志数据来源

`changeLog` 统一存储两类记录：

```javascript
ledger.changeLog = [
  // 编辑类
  { type:'edit', time:'2026-06-15 14:30:00', operator:'张建国',
    reason:'编制数由编办最新批复调整为92',
    changes: { careerQuota: { old:88, new:92 } } },
  // 审核类
  { type:'approve', time:'2026-06-10 09:15:00', operator:'李振华',
    action:'审核通过' },
  // 申报类
  { type:'submit', time:'2026-06-08 08:00:00', operator:'王玉兰',
    action:'学校提交申报' },
  // 退回类
  { type:'return', time:'2026-06-07 16:00:00', operator:'李振华',
    action:'退回修改', reason:'编制数核定有误' }
];
```

### 3.4 各操作写入 changeLog 的时机

| 操作 | 触发函数 | type | 记录内容 |
|------|----------|:--:|------|
| 学校提交 | `submitLedger()` (school) | `submit` | action: '学校提交申报' |
| 审核通过 | `approveLedger()` | `approve` | action: '审核通过' |
| 退回修改 | `confirmReturn()` | `return` | action: '退回修改', reason |
| 编辑保存 | `confirmSaveEdit()` | `edit` | reason, changes |

### 3.5 交互逻辑

- 查看页和编辑页均展示右侧变更记录卡片
- 按时间倒序排列
- 不同类型的节点用不同颜色圆点区分（蓝=提交、绿=审核通过、红=退回、蓝灰=编辑）
- 编辑类节点展开显示变更字段明细（旧→新）
- 无记录时显示"暂无变更记录"
- 卡片 `position: sticky; top: 76px` 跟随滚动
