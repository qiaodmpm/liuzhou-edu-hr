# 优化方案：学校台账页卡片区排序

> 日期：2026-06-15 | 状态：方案确认中，暂未实施

---

## 一、当前顺序

```
┌─ 编制概览（双卡+环形图）──────────────┐  ← 1
├─ 岗位结构（分类表+等级分布）───────────┤  ← 2
├─ 领导职数（汇总+厅处科）──────────────┤  ← 3
├─ 机构基础信息（校名/区域/级别/性质...）─┤  ← 4
└──────────────────────────────────────┘
```

**问题**：机构基础信息（学校叫什么、什么级别）放在最末尾，用户需要翻到底部才能看到基本信息。领导职数插在岗位结构和机构信息之间，逻辑断裂。

## 二、建议顺序

```
┌─ 机构基础信息（校名/区域/级别/性质...）─┐  ← 1  先知道"这是谁"
├─ 编制概览（双卡+环形图）──────────────┤  ← 2  再看"有多少编制"
├─ 岗位结构（分类表+等级分布）───────────┤  ← 3  再看"岗位怎么分"
├─ 领导职数（汇总+厅处科）──────────────┤  ← 4  最后看"领导配置"
└──────────────────────────────────────┘
```

## 三、逻辑依据

| 顺序 | 卡片 | 回答的问题 | 依赖关系 |
|:--:|------|------|------|
| 1 | 机构基础信息 | 这是哪个学校？什么级别？ | 无依赖，基础身份 |
| 2 | 编制概览 | 编制总量多少？用了多少？剩多少？ | 编制数由机构级别决定 |
| 3 | 岗位结构 | 岗位怎么分？每个等级多少人？ | 岗位总量 ≤ 编制总量 |
| 4 | 领导职数 | 校领导配额多少？实配多少？ | 领导职数 ≤ 管理岗位数 |

自上而下的信息流：**身份 → 总量 → 分配 → 领导**

## 四、改动范围

`org-ledger-school.html` 中 `renderPage()` 函数，调整 4 个渲染函数的调用顺序：

```diff
  if (showForm) {
    h += renderEditForm(ledger, comp);
  } else {
+   // 机构基础信息
+   h += renderBasicInfo(ledger, false);
    // 编制概览（双卡 + 环形图）
    h += renderQuotaDashboard(ledger, comp);
    // 岗位结构
    h += renderPostStructure(ledger, comp, false);
    // 领导职数
    h += renderLeaderInfo(ledger, false);
-   // 机构基础信息
-   h += renderBasicInfo(ledger, false);
  }
```

同时编辑模式（`renderEditForm`）保持一致顺序：基础信息 → 编制信息 → 岗位结构 → 领导职数（当前已基本正确）。
