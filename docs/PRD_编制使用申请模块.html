1. 模块概述

1.1 业务背景

学校在招聘教师或调动人员前，须向机构编制委员会办公室（编办）提交编制使用计划申请。编办线下审批通过后，学校方可使用编制名额。本模块实现申请、审核、编办确认的全流程线上化。

1.2 双轨说明

轨道表单依据编制类型管理模式
事业编附件2（事业单位编制使用计划申报表）实名制事业编制核定编制数 − 实有在编人数 − 已批复计划数
控制数附件9（中小学聘用教师控制数使用计划申报表）备案制聘用教师控制数核定控制数 − 实有控制数人数 − 已批复控制数

1.3 使用类型（6 种）

编码名称适用编制类型
publicRecruit统一公开招聘事业编 / 控制数
selfRecruit单位自主实施招聘事业编 / 控制数
talentMid中高级人才招聘事业编 / 控制数
talentHigh引进高层次人才事业编 / 控制数
transfer调动事业编 / 控制数
other其他事业编 / 控制数

1.4 角色与权限

角色权限范围核心操作
市管理员 (city)全市数据查看；仅可审核市直属学校批次管理、审核（一审+二审）、导出、查看全部
区管理员 (district)本区数据查看；仅可审核本区属学校批次管理、审核（一审+二审）、导出
校管理员 (school)本校数据新建申报、修改重提、提交编办确认、上传后续材料、导出
教师 (teacher)无权限不可访问本模块
系统管理员 (admin)无权限不可访问本模块（仅限系统配置功能）
权限隔离规则： 市管理员只能审核市直属学校的申请，不能审核区属学校；区管理员只能审核本区属学校的申请。列表页操作按钮根据 canApprove(orgName, district) 动态显示/隐藏。

2. 批次管理

2.1 批次类型

类型标识创建方式提交限制典型场景
定向批次B{year}-{seq}市/区管理员手动创建每校每种编制类型限 1 次年度集中申报
自主申报批次A{year}-{seq}系统自动生成，全年存在不限次数紧急/零星需求⏳ 暂不支持，后续版本实现
⏳ 自主申报批次（AUTO）暂不支持：当前版本仅实现定向批次。AUTO 批次的自动创建、自动关闭、不限次数提交、绿色边框标识等能力将在后续版本中实现。以下规则为规划中的设计，当前原型中可忽略。

AUTO 批次规则（规划中，暂未实现）

规则说明
生命周期每年 1 月 1 日系统自动生成，12 月 31 日自动关闭
可见范围市直属学校看到 AUTO 批次（发布单位：市教育局）；区属学校看到 AUTO 批次（发布单位：区教育局）
重复提交同一学校同一编制类型可多次提交，不限制次数
视觉标识AUTO 批次卡片左侧有绿色边框，区别于定向批次的蓝色边框

2.2 批次状态（3 种）

状态值中文标签含义学校操作主管操作
pending未开始批次已创建但尚未到达申报开始时间仅可查看，不可填报可编辑、可删除
active进行中批次处于开放申报窗口期可申报、驳回可重提、导出审核、编辑、手动关闭、导出
closed已结束申报窗口已关闭仅可查看历史记录审核、导出、可编辑
未开始(pending) ──(达到开始时间)──→ 进行中(active) │ ┌─────────────┤ │ (到期自动) │ (手动提前结束) ▼ ▼ 已结束(closed) ←───┘

2.3 批次创建

字段输入类型必填说明
批次名称<input type="text">是不能重复
年度<select>是创建后不可修改
申报开始日期<input type="date">是从当天 00:00:00 开始
申报截止日期<input type="date">是截止到当天 23:59:59；截止日 ≥ 开始日
适用范围<select>是全市 / 指定区 / 指定学校。市管理员可选"全市"，区管理员仅能选本区
备注说明<textarea>否最多 200 字

2.4 批次编辑（条件可编辑）

字段批次状态可编辑说明
批次名称全部✅随时可改
年度全部❌创建后永久锁定
申报开始日期未开始✅申报开始后锁定
申报开始日期进行中 / 已结束❌申报已开始，不允许修改
申报截止日期未开始 / 进行中✅
申报截止日期已结束❌批次已结束，不允许修改
适用范围全部❌创建后永久锁定
备注说明全部✅最多 200 字

2.5 批次卡片统计规则

批次卡片展示事业编 / 控制数的 已申报数 / 总数：

  • 已申报数：该批次下已提交申报的 去重学校数量（同一学校多次提交算 1 所）
  • 总数：该批次适用范围覆盖的学校总数（非提交数），由 countSchoolsInScope(scope) 计算

如果批次选"全市"→ 总数 = 全市学校数；选"指定区"→ 总数 = 该区学校数；选"指定学校"→ 总数 = 选定学校数。

2.6 批次详情弹框

展示批次完整信息：编号、名称、年度、起止日期、适用范围、状态、备注说明（悬停 tooltip 展示全文）。

事业编和控制数分别展示：已申报学校数 / 覆盖学校数、各状态（待一审/一审通过/待二审/已完成/一审驳回）的统计数。

3. 申请状态与流转

3.1 状态枚举（5 种）

状态值中文标签印章颜色含义
submitted待一审黄色学校已提交，等待主管单位初审
first_approved一审通过绿色主管单位初审通过，等待学校提交编办确认
final_submitted待二审黄色学校已提交编办批复文件，等待主管单位终审
approved已完成绿色编办确认完成，编制名额生效（终态）
rejected一审驳回红色申请被驳回，可修改重提
注意：本项目不支持"保存草稿"功能。表单提交后直接进入 submitted 状态 —— 不要添加"保存草稿"按钮或草稿状态。

3.2 状态流转图

学校提交 ──→ submitted (待一审) │ ┌───────┤ │ 驳回 │ 一审通过 ▼ ▼ rejected first_approved (一审通过) │ │ │ 学校上传编办文件 + 填写确认数 │ │ │ ▼ │ final_submitted (待二审) │ │ │ ┌────┤ │ │驳回 │ 通过 │ ▼ ▼ └─→ rejected approved (已完成·终态) （修改重提）

3.3 各状态下角色操作矩阵

状态校管理员区/市管理员（有权限）
submitted查看审核（一审通过 / 驳回）
first_approved查看、提交编办确认、导出查看
final_submitted查看审核（二审通过 / 驳回）
approved查看、导出、上传后续材料查看、导出、下载汇总表
rejected查看、修改重提查看

6. 表单页详细设计（staffing-form.html）

6.1 申报类型选择

页面顶部有两个大卡片：🏛 事业编（附件2）/ 📋 控制数（附件9），点击切换。

修改重提模式（isEditMode = true）：申报类型锁定，卡片半透明 + cursor: not-allowed，下方显示"修改重提不可更改"，点击无效。

6.2 单位信息（系统自动填充，全部只读）

事业编

#字段名说明
1单位全称从 SCHOOL_PROFILE 读取
2机构级别如"正科级"
3单位性质如"全额拨款事业单位"
4核定编制数
5实有在编人数
6已批复计划数系统计算

8未使用计划数= 已批复 − 已使用

控制数

#字段名说明
1单位全称同上
2机构级别同上
3单位性质同上
4核定控制数
5实有控制数人数
6已批复控制数系统计算
7已使用控制数系统计算
8未使用控制数= 已批复 − 已使用
9可申请控制数= max(0, 核定 − 实有 − 已批复 − 到期占用中)

6.3 使用类型明细表（6 行）

列字段类型必填校验规则
1使用形式只读文本—固定 6 种
2使用人数<input type="number">否≥ 0 整数；总额 > 0

汇总行：实时计算 SUM(num)，显示在表格底部。

6.4 名额汇总栏（实时计算）

指标说明颜色
可申请编制数 / 可申请控制数系统计算—
本次申请合计= SUM(使用人数)—
剩余= 可用 − 申请≥ 0 绿色 / < 0 红色

如果申请合计 > 可用数，提交按钮仍可点击但会显示红色警告。

6.5 附件上传

属性说明

必填是（必须上传才能提交）

6.6 提交流程

  1. 选择编制类型 → 单位信息自动填充 → 填写使用类型明细 → 上传附件
  2. 点击"提交申报"
  3. 校验：① 申请合计 > 0；② 人数 > 0 的行已填学历；③ 附件已上传
  4. 通过 → 生成申请编号 → 状态设为 submitted → 存入 localStorage → toast 提示 → 跳转回列表
  5. 不通过 → toast 提示具体未通过项

6.7 修改重提模式

属性说明
触发条件URL 带 ?id=xxx 参数（isEditMode = true）
数据预填所有字段预填原申请数据（useForms 明细、附件状态等）
编制类型锁定不可修改（卡片半透明 + 禁止点击 + 提示文字）
其他字段全部可编辑
提交后状态重置为 submitted，重新走一审流程；时间线追加 resubmit 事件

8. 审核页详细设计（主管单位视角）

8.1 页面布局

与详情页相同的左右两栏布局：

  • 左栏：单位信息 + 使用类型明细表 + 名额汇总 + 附件
  • 右栏：申报基本信息卡片 + 审核操作按钮（通过/驳回）+ 审批时间线

8.2 标题栏

页面标题"编制使用申请审核"，右侧显示圆形印章戳（根据状态变色：待一审黄色、一审通过绿色、待二审黄色、已完成绿色、已驳回红色）。

8.3 印章戳样式

72px 圆形印章，虚线内边框，-8° 旋转。5 种颜色变体：

状态印章文字颜色
submitted待一审黄色
first_approved一审通过绿色
final_submitted待二审黄色
approved已完成绿色
rejected已驳回红色

8.4 审核操作

一审（submitted 状态）

  • 通过：确认弹框 → 确认 → 状态变为 first_approved，时间线追加 first_approve 事件
  • 驳回：驳回弹框（必填驳回原因 textarea） → 确认 → 状态变为 rejected，时间线追加 reject 事件（含驳回原因）

二审（final_submitted 状态）

  • 通过：确认弹框 → 确认 → 状态变为 approved，时间线追加 approve 事件
  • 驳回：驳回弹框 → 状态变为 rejected

权限隔离

审核按钮仅对有权限的用户显示（市管理员仅市直属、区管理员仅本区）。first_approved 和 approved 状态下不显示审核按钮。

8.5 数据一致性

审核页同样通过 localStorage.staffing_submissions 获取权威状态数据，确保与列表页状态一致。

11. 编制池联动机制

11.1 概述

编制使用申请模块是编制生命周期的入口。申请通过后，批复的编制名额进入"编制可用池"，供教师入编、招聘岗位申请等下游模块关联和消耗。

11.2 联动数据流

编制使用申请 approved │ ▼ ┌──────────────────────────────┐ │ 编制可用池 │ │ approvedPlan += 批复数 │ │ validStart / validEnd 写入 │ └──────────────────────────────┘ │ ├──→ 教师入编关联 ──→ usedPlan += 入编人数 │ ├──→ 招聘申请关联 ──→ pendingAudit += 申请人数（提交时） │ ──→ usedPlan += 终审通过人数 │ └──→ 教师出编通过 ──→ usedPlan −= 出编人数（释放）

11.3 关键计算

指标公式说明
可用编制approvedPlan − usedPlan − pendingAudit入编/招聘模块的剩余名额上限
已批复编办确认的累计数仅 approved 状态计入
已使用入编通过 + 招聘终审通过实际占用
在途招聘申请待审核临时占坑，驳回后释放

11.4 编制有效期对下游的影响

状态下游行为
有效期内入编/招聘可正常关联此编制批次
已过期入编/招聘页面的批次下拉列表中不显示或标记"已过期"；不可选
即将到期（≤30 天）黄色警告标签，仍可选但提示
