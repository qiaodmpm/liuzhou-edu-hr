# 修改密码功能 — 产品方案

> 日期：2026-06-17 | 版本：v1.0 | 状态：✅ 已实施

---

## 1. 模块概述

为平台两大用户群体（管理员、教师）提供统一的密码修改能力，支持在任意页面通过顶部导航栏用户下拉菜单触发，以模态框形式完成密码修改，无需跳转页面。

## 2. 用户角色与场景

| 角色 | 账号存储 | 当前密码 | 是否需要修改密码 |
|------|---------|---------|:--:|
| 市管理员 (city) | 硬编码 demo 账号 | `Edu@2025` | ✅ |
| 区管理员 (district) | 硬编码 demo 账号 | `Edu@2025` | ✅ |
| 校管理员 (school) | 硬编码 demo 账号 | `Edu@2025` | ✅ |
| 教师 (teacher) | `localStorage.teacher_accounts` | 初始密码 / 已改过 | ✅ |

> **说明**：管理员账号当前仅有硬编码 demo 数据。为支持修改密码，需新增 `localStorage.admin_accounts` 存储，首次使用时自动从 demo 数据初始化。

## 3. 功能清单

| # | 功能 | 说明 |
|---|------|------|
| F1 | 修改密码入口 | 顶部导航栏用户下拉菜单中的「修改密码」链接 |
| F2 | 旧密码验证 | 输入当前密码，验证通过后方可修改 |
| F3 | 新密码设置 | 新密码 + 确认密码，含强度检测和规则校验 |
| F4 | 密码规则 | 8-20 位，包含大写、小写、数字 |
| F5 | 密码强度指示 | 弱 / 中 / 强 三档 |
| F6 | 管理员密码持久化 | 写入 `localStorage.admin_accounts` |
| F7 | 教师密码持久化 | 写入 `localStorage.teacher_accounts` |
| F8 | 成功反馈 | Toast 提示 + 模态框关闭 |

## 5. UI 设计

### 5.1 模态框

- 宽度 440px，居中显示
- 标题：🔑 修改密码
- 右上角关闭按钮 ×
- 背景半透明遮罩

### 5.2 表单字段

| 字段 | 类型 | 必填 | 说明 |
|------|------|:--:|------|
| 当前密码 | password | ✅ | 输入框 + 眼睛切换可见性 |
| 新密码 | password | ✅ | 输入框 + 眼睛切换可见性 |
| 确认密码 | password | ✅ | 输入框 + 眼睛切换可见性 |

### 5.3 密码强度条

```
████████████░░░░░░░░░░  弱（红色）
██████████████████░░░░  中（黄色）
██████████████████████  强（绿色）
```

强度判定：
- **弱**：仅满足长度要求（8-20 位）
- **中**：长度 + 包含至少 2 类字符（大写/小写/数字）
- **强**：长度 + 包含全部 3 类字符（大写+小写+数字）

### 5.4 规则清单（实时校验）

```
☐ 8-20 位字符
☐ 至少包含 1 个大写字母
☐ 至少包含 1 个小写字母
☐ 至少包含 1 个数字
☐ 新密码不能与当前密码相同
☐ 两次密码输入一致
```

输入时实时逐条打勾 ✅ / ⬜。

## 7. 业务规则

| # | 规则 | 说明 |
|---|------|------|
| R1 | 旧密码必须正确 | 验证失败提示"当前密码错误" |
| R2 | 新密码 ≠ 旧密码 | 相同则提示"新密码不能与当前密码相同" |
| R3 | 密码 8-20 位 | 前端实时校验，提交时再次校验 |
| R4 | 含大写、小写、数字 | 缺一类则拦截 |
| R5 | 两次输入一致 | 不一致则拦截 |
| R6 | 修改后重新登录 | 密码更新后清除 `currentUser`，跳转登录页 |

## 8. 实施计划

### 8.1 文件改动清单

| 文件 | 改动 |
|------|------|
| `index.html` | 管理员登录优先从 `admin_accounts` 读取密码 |
| **新增** `change-password-modal.html` | 独立模态框组件（或内嵌到各页面） |

> **推荐方案**：将修改密码模态框的 HTML + CSS + JS 封装为一个独立片段，通过 `fetch` 注入到各页面，避免在每个页面重复代码。若项目不接受 fetch 方案，则直接在 `workbench.html` 和各主要列表页中复制模态框片段。

### 8.2 实际实施策略

考虑到项目架构（无前端框架、无构建工具、页面独立），**最优方案是在各需要修改密码的页面内嵌模态框片段**。但页面数量多（20+），维护成本高。

**折中方案**：仅在全站共用的 2 个入口实现：

| 入口 | 说明 |
|------|------|
| `workbench.html` | 所有用户登录后的工作台，覆盖最广 |
| `personal-center.html` | 个人中心页，已有的"修改密码"入口 |

其他页面的「修改密码」链接统一跳转到 `personal-center.html` 的修改密码锚点。

## 9. 边界场景

| 场景 | 处理 |
|------|------|
| 管理员首次修改密码 | `admin_accounts` 不存在 → 从 demo 数据自动初始化 |
| 教师首次修改密码（非 first-login 场景） | `teacher_accounts` 中已有记录 → 直接更新 password 字段 |
| 用户取消修改 | 关闭模态框，不写入任何数据 |
| 修改后未重新登录 | `currentUser` 已清除，下次刷新页面会跳到登录页 |
| `admin_accounts` 已被初始化过 | 直接读取并更新对应记录 |
| 教师无 `teacher_accounts` 匹配记录 | 提示"账号数据异常，请联系管理员" |
