# 迭代计划：编制使用申请模块

当前现状：`staffing-application.html` 已完成批次管理 + 控制数单线申报 + 基础审核流转。
目标：补齐业务规则中的缺失项，完成核心流程闭环。

---

## P0 — 核心流程闭环

### P0-1：编制类型双轨（事业编 / 控制数）

**当前问题**：只有"控制数"（附件9）一条线，缺少"事业编"（附件二）。

**改造点**：
- 批次内申报增加编制类型选择（事业编 / 控制数）
- 每种类型各自对应不同的申报表格（附件二 / 附件九）
- 每种类型每个机构每批次限申报 **1 次**
- 审核列表按编制类型区分展示

**影响范围**：
- `staffing-application.html` — 学校申报入口、审核列表
- `staffing-form.html` — 申报表单按类型切换

---

### P0-2：审批结果录入模块

**当前问题**：审核通过即结束，缺少编办最终审批结果的录入环节。

**改造点**：
- 市/区管理员对已通过的申报录入"编办审批结果"
  - 计划使用人数（≤ 学校申报人数，自动校验）
  - 使用期限
- 上传附件存档（选填）
- 编办未通过 → 驳回操作
- 新增审批结果状态："待编办审批" / "编办已批准" / "编办已驳回"

**影响范围**：
- `staffing-application.html` — 操作入口
- `staffing-detail.html` — 审批结果展示
- 新建审核页或扩展现有审核页

---

### P0-3：数据联动（编办通过后更新编制余额）

**当前问题**：审批通过后不更新学校的编制数据。

**改造点**：
- 编办审批通过后，自动将计划使用人数累加到对应学校的数据：
  - 事业编类型 → 增加"未使用编制数"
  - 控制数类型 → 增加"未使用控制数"
- 数据联动记录可追溯

**影响范围**：
- 数据模型扩展
- 审批结果录入的联动逻辑

---

## P1 — 业务完整性

### P1-1：自主申报入口

**当前问题**：只能通过批次入口申报，没有自主申报通道。

**改造点**：
- 学校管理员"编制使用申请"页增加"自主申报"按钮
- 自主申报默认归属到"自主申报批次"（虚拟批次）
- 自主申报同样区分事业编 / 控制数两种类型

**影响范围**：
- `staffing-application.html` — 学校视角 UI

---

### P1-2：导出申请表（线下盖章用）

**当前问题**：审核通过后无法导出申请表用于线下盖章。

**改造点**：
- 审核通过后，学校管理员可导出 PDF/Word 申请表
- 导出模板按编制类型区分：
  - 事业编 → 附件2（一式 3 份，正反双面打印）
  - 控制数 → 附件9（一式 3 份，正反双面打印）
- 导出内容包含学校基本信息、编制数据、申请详情、签章位

**影响范围**：
- `staffing-detail.html` — 导出按钮
- 新增导出模板

---

### P1-3：批次汇总表导出

**当前问题**：批次发起人（市/区管理员）无法在批次结束后导出汇总数据。

**改造点**：
- 批次结束后，批次发起人可导出单批次汇总表
  - 事业编批次 → 附件3（9 种用编形式）
  - 控制数批次 → 附件10（4 种使用形式）
- 替换当前占位按钮 `showToast('导出汇总数据（附件10）')`

**影响范围**：
- `staffing-application.html` — 批次卡片的"导出"按钮

---

### P1-4：年度编制使用报告表导出

**当前问题**：无跨批次年度汇总功能。

**改造点**：
- 可导出全年跨批次、跨类型的年度编制使用报告（附件4）
- 包含已办理入编/未办理入编的使用情况明细（姓名、报送日期、人数）

**影响范围**：
- 新增报告页面或入口

---

## P2 — 数据质量与体验

### P2-1：编制数据外部对接

**当前问题**：编制数据硬编码在 demo 数据中。

**改造点**：
- 预留接口从"柳州市人工智能助推教师队伍建设管理平台"获取：
  - 核定事业编制数
  - 在编人数
  - 聘用控制数
- 对接前保持当前 mock 数据可用

**影响范围**：
- 数据获取层
- `staffing-form.html` — 只读展示编制数据

---

### P2-2：校管理员权限约束校验

**当前问题**：前端申报页面可能允许修改编制数据。

**改造点**：
- 校管理员视角下，编制数据字段设为只读
- 提交时后端校验，拒绝校管理员修改编制的请求

**影响范围**：
- `staffing-form.html` — 字段 disabled 状态
- 后端校验逻辑（如有）

---

## 迭代建议

```
第 1 轮（核心闭环，1-2 天）
  P0-1 编制类型双轨 → P0-2 审批结果录入 → P0-3 数据联动

第 2 轮（业务补全，1-2 天）
  P1-1 自主申报 → P1-2 导出申请表 → P1-3 批次汇总表导出 → P1-4 年度报告表导出

第 3 轮（长期优化）
  P2-1 外部数据对接 → P2-2 权限约束校验
```
