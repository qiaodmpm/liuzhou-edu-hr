## 5. 功能清单（含业务规则）

---

### F01.01 创建批次

**功能说明**：管理员创建定向申报批次，设置名称、年份、日期、适用范围。学校在批次内提交编制使用申请。

**适用角色**：市管理员、区管理员 | **优先级**：P0

**前置条件**：无

**后置条件**：新批次出现在批次列表中，状态为 open（进行中），学校可在批次内新建申请

**业务规则**：
- 批次名称不可重复（当前所有批次范围内唯一）
- 截止日期 ≥ 开始日期，否则 toast 提示
- 市管理员可选"全市"或"指定区"；区管理员仅能选本区
- 自主申报批次（AUTO-{year}）无需手动创建，系统每年 1 月 1 日自动生成

**交互流程**：点击列表页"新建批次"按钮 → 弹出模态框（见 §4.1.5）→ 填写 → "确认创建" → 列表刷新

---

### F01.02 编辑批次

**功能说明**：修改进行中批次的基本信息（名称、日期、适用范围）

**适用角色**：市管理员、区管理员 | **优先级**：P1

**前置条件**：批次状态为 open（进行中）；非自主申报批次（AUTO-{year} 不可编辑）

**后置条件**：批次信息更新，列表刷新

**业务规则**：
- 同 F01.01：名称唯一、日期约束、权限约束
- 已关闭（closed）批次不可编辑，按钮隐藏
- 编辑不改变该批次下已提交的申请记录

**交互流程**：点击批次卡片"编辑"按钮 → 模态框预填当前值 → 修改 → 保存 → 列表刷新

---

### F01.03 关闭批次

**功能说明**：关闭进行中批次，停止该批次下的新申报

**适用角色**：市管理员、区管理员 | **优先级**：P1

**前置条件**：批次状态为 open（进行中）；非自主申报批次

**后置条件**：批次状态变为 closed（已结束），学校不可在该批次下新增申请

**业务规则**：
- 关闭后**不可恢复**，需二次确认弹框
- 已提交的申请不受影响，继续走审批流程
- 自主申报批次由系统在每年 12 月 31 日自动关闭，不提供手动关闭入口
- 若批次截止日期已过但未手动关闭，学校端列表中标记"已截止"，不可新建申请

**交互流程**：点击批次卡片"关闭"按钮 → 确认弹框 → 状态更新 → 列表刷新

---

### F01.04 查看批次详情

**功能说明**：弹窗展示批次的完整信息及该批次下各编制类型的申请统计数据

**适用角色**：市/区/校管理员 | **优先级**：P1

**前置条件**：无

**后置条件**：无（纯查看，无数据变更）

**展示内容**：批次编号、名称、年份、发布单位、日期范围、适用范围、状态、事业编申请数、控制数申请数

**交互流程**：点击批次卡片 → 弹出模态框展示详情 → 关闭

---

### F01.05 批次按年份筛选

**功能说明**：通过下拉选择年份，即时过滤批次卡片列表

**适用角色**：市/区/校管理员 | **优先级**：P1

**前置条件**：存在多个年份的批次

**后置条件**：批次卡片列表按所选年份过滤

**业务规则**：
- 下拉选项：全部年份 / 2026 / 2025 / 2024（动态生成）
- "全部年份"显示所有批次，含自主申报批次（AUTO-{year}）
- 选择后前端即时过滤，无需请求

### F02.01 新建申请

**功能说明**：学校管理员选择编制类型（事业编/控制数），进入表单页填写编制使用申请

**适用角色**：校管理员 | **优先级**：P0

**前置条件**：
- 批次状态为 open（进行中）或为自主申报批次（AUTO-{year}）
- 定向批次下该编制类型尚未提交过（防重复标记检查）

**后置条件**：跳转至 staffing-form.html，URL 携带 batchId 和 staffingType 参数

**业务规则**：
- 定向批次每校每种编制类型**限 1 次**；重复点击 toast 提示"该批次该类型已申报"，阻止跳转
- 自主申报批次不限次数，可多次提交
- 防重复通过 localStorage 标记 sub_{batchId}_{type} 实现
- 当学校在定向批次内只提交了一种编制类型时，列表顶部显示提示条：您还未提交[另一种编制类型]的申报，带快捷申报链接

**交互流程**：点击批次"新建申请" → 检查防重复标记 → 通过则跳转表单页；不通过则 toast 阻止

---

### F02.02 填写单位信息（自动填充）

**功能说明**：系统自动从 SCHOOL_PROFILE 加载学校的编制数据并展示，全部字段只读

**适用角色**：校管理员 | **优先级**：P0

**前置条件**：已选择编制类型（career — 事业编 / control — 控制数）

**后置条件**：单位信息卡片渲染完毕，数据填充到位

**业务规则**：
- 校管理员**无权修改**任何编制数据，所有字段设为只读
- 事业编显示 9 字段：核定编制数、实有在编人数、已批复计划数、已使用计划数、未使用计划数、可申请编制数等
- 控制数显示 9 字段：核定控制数、实有控制数人数、已批复控制数、已使用控制数、未使用控制数、可申请控制数等
- 计算公式前端实时执行（如 可申请 = 核定 - 实有 - 已批复），计算结果标注在字段旁
- 数据来源：外部平台系统数据（当前为 DEMO 模拟数据）

---

### F02.03 填写使用类型明细

**功能说明**：填写 6 种使用类型各自的人数、学历条件、相关条件、备注

**适用角色**：校管理员 | **优先级**：P0

**前置条件**：单位信息已加载

**后置条件**：使用类型明细数据暂存前端数组，实时更新汇总行和名额栏

**业务规则**：
- 6 种使用类型固定不可增减：统一公开招聘 / 自主实施招聘 / 中高级人才招聘 / 引进高层次人才 / 调动 / 其他
- 每种人数 ≥ 0，为整数
- **申请总人数必须 > 0**，否则提交时阻止
- **人数 > 0 的行必须填写学历/专业/资格字段**，前端标红提示
- 申请总数 ≤ 可申请编制数（事业编）/ 可申请控制数（控制数）；超出时名额栏显示红色警告
- 学历字段 ≤ 200 字符；条件/备注字段 ≤ 500 字符
- 每种人数边界：0 ≤ 值 ≤ 999

**交互流程**：输入数字 → 即时更新汇总行和名额栏（§4.2.6）→ 人数 > 0 时学历字段标红必填

---

### F02.04 上传附件

**功能说明**：上传申请表附件（事业编上传附件2，控制数上传附件9），用于线下报送编办

**适用角色**：校管理员 | **优先级**：P0

**前置条件**：已选择编制类型

**后置条件**：文件暂存前端状态，显示文件名和大小

**业务规则**：
- 支持格式（白名单）：.pdf / .jpg / .jpeg / .png / .doc / .docx / .xls / .xlsx
- 禁止格式（黑名单）：.zip / .rar / .7z / .tar / .gz / .bz2 / .xz / .tgz（所有压缩包）
- 大小上限：单文件 ≤ 10MB
- 必须上传：提交时附件为空则阻止提交，toast 提示"请上传附件"
- 当前为单文件模式，替换上传时自动移除旧文件
- 附件格式不合规 → toast 提示具体不支持的格式
- 附件超 10MB → toast 提示"文件超过10MB限制"

**交互流程**：拖拽或点击上传区 → validateFile() → 通过：显示文件名+大小+绿色勾；不通过：toast 提示 → 可点击移除

---

### F02.05 提交申请

**功能说明**：校验所有必填项后提交申请，生成申请编号并写入存储

**适用角色**：校管理员 | **优先级**：P0

**前置条件（全部满足才可提交）**：
1. 单位信息完整且正确
2. 申请总人数 > 0
3. 申请总数 ≤ 可申请编制数/控制数
4. 所有人数 > 0 的行已填写学历/专业/资格
5. 附件已上传

**后置条件**：
- 生成申请编号 S{YYYYMMDD}{序号}（如 S20260611001）
- 状态设为 submitted — 待一审
- 写入 localStorage staffing_submissions
- 定向批次写入防重复标记 sub_{batchId}_{type}
- 1 秒后自动跳转回列表页

**业务规则**：
- 提交后**不可撤回**，无草稿功能
- 可申请编制数为 0 或负数时，提交按钮置灰，名额栏红色警告"名额不足"
- localStorage 被清除时，首次加载 SEED 数据自动初始化

**交互流程**：点击"提交申报" → 遍历全部 5 项前置条件校验 → 全部通过 → saveSubmissionRecord() → toast"提交成功" → 1 秒后跳转列表页

---

### F02.06 提交编办确认

**功能说明**：一审通过后，学校上传编办批复文件，填写各类型确认数和编制有效期，提交二审

**适用角色**：校管理员 | **优先级**：P0

**前置条件**：申请状态为 first_approved — 一审通过

**后置条件**：状态变为 final_submitted — 待二审；申报履历追加 final_submit 事件

**业务规则**：
- 逐行填写编办确认数：0 ≤ 确认数 ≤ 学校申请数；输入框即时校验，超出 toast 阻止
- 确认总数可小于申请总数（编办可能砍额度）
- 编制有效期截止 ≥ 起始；截止早于起始时日期选择器阻止
- 需上传编办批复文件（格式同 F02.04）
- 确认数和有效期均填完后才可提交

**交互流程**：弹出编办确认弹框（§4.3.6）→ 逐行填写确认数 → 选择有效期 → 上传批复文件 → submitFinalConfirm() → 状态更新

---

### F02.07 驳回后修改重提

**功能说明**：被驳回的申请可修改后重新提交，预填原申请数据，重新走一审流程

**适用角色**：校管理员 | **优先级**：P0

**前置条件**：申请状态为 rejected — 驳回

**后置条件**：状态回到 submitted — 待一审；申报履历追加 resubmit 事件

**业务规则**：
- 修改时表单预填原申请数据，学校可调整任意字段
- 重新提交后重置为 submitted，从头走一审流程
- 驳回原因在时间线中可见（红色背景框），供学校参考修改

**交互流程**：点击"修改重提" → 跳转表单页（URL 带 ?id=xxx，预填数据）→ 修改 → 提交 → 状态更新

---

### F02.08 上传后续材料

**功能说明**：已完成的申请可补充上传后续材料，不改变审批状态

**适用角色**：校管理员 | **优先级**：P1

**前置条件**：申请状态为 approved — 已完成

**后置条件**：记录的 followUp 标记为 true，文件追加到附件列表

**业务规则**：
- 材料格式限制同 F02.04（支持 pdf/jpg/png/doc/xls；禁止压缩包；≤10MB）
- 不改变审批状态，纯粹的材料补充
- 可多次上传，追加而非替换

**交互流程**：点击"上传后续材料" → 弹出上传弹框 → 选择文件 → 上传 → toast"上传成功"

### F03.01 一审通过

**功能说明**：主管单位（市/区管理员）审核学校提交的编制申请，审核通过

**适用角色**：市管理员（仅市直属学校）、区管理员（仅本区属学校） | **优先级**：P0

**前置条件**：
- 申请状态为 submitted — 待一审
- canApprove(school) === true（权限隔离检查）

**后置条件**：状态变为 first_approved — 一审通过；申报履历追加 first_approve 事件

**业务规则**：
- 权限隔离：市管理员仅能审核 schoolCategory === "市直属" 的学校；区管理员仅能审核 schoolCategory === "鱼峰区属" 的学校
- 无权限的记录不显示审核按钮

**交互流程**：进入详情页 → 点击"通过"按钮 → 确认弹框（§4.1.6）→ 确认 → 状态更新 → 列表刷新

---

### F03.02 一审驳回

**功能说明**：主管单位驳回学校提交的编制申请，要求修改后重提

**适用角色**：同 F03.01 | **优先级**：P0

**前置条件**：同 F03.01

**后置条件**：状态变为 rejected — 驳回；申报履历追加 reject 事件（含驳回原因，红色背景框）

**业务规则**：
- 驳回原因必填，不可为空，不可仅空格
- 驳回原因为空时"确认驳回"按钮无效，toast 提示"请填写驳回原因"
- 驳回原因 ≤ 500 字符

**交互流程**：进入详情页 → 点击"驳回"按钮 → 驳回弹框 → 填写驳回原因 → confirmReject() → 校验非空 → toast → 列表刷新

### F03.03 二审通过（编办确认）

**功能说明**：学校提交编办文件后，主管单位终审通过，编制名额正式生效

**适用角色**：同 F03.01 | **优先级**：P0

**前置条件**：
- 申请状态为 final_submitted — 待二审
- 学校已提交编办批复文件及确认数

**后置条件**：
- 状态变为 approved — 已完成（终态）
- 编制名额进入可用池，有效期为学校提交的日期范围
- 系统自动将批复的计划使用人数累加到对应学校的"未使用编制数"或"未使用控制数"

**业务规则**：
- 通过后编制生效，有效期按学校提交日期起算
- 编制有效期状态：有效期内（绿色）/ 即将到期 ≤30 天（黄色警告）/ 已过期（红色，下游模块不可选）
- 下游模块（入编/招聘）关联时检查有效期

**交互流程**：点击"审核"→ 确认弹框 → 确认通过 → 状态更新 → 编制池联动

### F03.04 二审驳回

- 同 F03.02：驳回原因必填，不可为空
- 驳回后学校可修改编办确认信息重新提交二审

**交互流程**：同 F03.02

### F04.01 提醒未提交学校

**功能说明**：管理员在"未提交"视图中提醒尚未提交申请的学校尽快申报

**适用角色**：市管理员、区管理员 | **优先级**：P2

**前置条件**：
- 该学校在选定批次内尚未提交任何申请
- 今日尚未提醒过该学校（每日每校每批次限 1 次）

**后置条件**：
- staffing_reminders[{batchId}|{schoolName}] 记录提醒时间 + 累计次数
- 按钮文案变为"今日已提醒"并置灰不可点击

**业务规则**：
- 每天每校每批次只能提醒 1 次；次日 0 点自动重置
- 数据持久化至 localStorage staffing_reminders（页面刷新不丢失）
- 记录累计提醒次数，列表可查

**按钮样式**：可提醒：白底蓝边；已提醒：灰底灰边，cursor:default

**交互流程**：选择批次 → 切换到"未提交"视图 → 点击"提醒申报" → 确认弹框 → 确认 → 按钮变"今日已提醒"置灰

## 6. 通用规则

### 6.1 权限矩阵总览

| 角色 | 可审核范围 | 判断逻辑 |
|---|---|---|
| 市管理员 | 仅市直属学校 | canApprove 检查 schoolCategory === "市直属" |
| 区管理员 | 仅本区属学校 | canApprove 检查 schoolCategory === "鱼峰区属" |
| 校管理员 | 无审核权限 | canApprove 始终返回 false |

### 6.2 附件上传通用规则

适用于编制使用申请、入编申请、出编申请等各类申请模块：

| 规则项 | 规则内容 |
|---|---|
| 支持格式 | .doc / .docx / .xls / .xlsx / .pdf / .jpg / .jpeg / .png / .gif |
| 禁止格式 | .zip / .rar / .7z / .tar / .gz / .bz2 / .xz / .tgz（所有压缩包） |
| 大小上限 | 单文件 ≤ 10MB |
| 上传方式 | 拖拽或点击上传区；替换上传时自动移除旧文件 |

### 6.3 编制池联动

编制使用申请 approved 后，批复名额进入可用池：

| 指标 | 公式 | 说明 |
|---|---|---|
| 可用编制 | approvedPlan - usedPlan - pendingAudit | 入编/招聘模块的剩余名额上限 |
| 已批复 | 编办确认的累计数 | 仅 approved 状态计入 |
| 已使用 | 入编通过 + 招聘终审通过 | 实际占用 |
| 在途 | 招聘申请待审核 | 临时占坑，驳回后释放 |

### 6.4 编制有效期对下游的影响

| 状态 | 下游行为 |
|---|---|
| 有效期内 | 入编/招聘可正常关联此编制批次 |
| 已过期 | 下拉列表中不显示或标记"已过期"，不可选 |
| 即将到期（≤30天） | 黄色警告标签，仍可选但提示 |
